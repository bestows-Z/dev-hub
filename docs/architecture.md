# DevHub 架构与交付设计

日期：2026-10-05

## 产品范围

- 公开站点：首页、文章列表和正文、友链、项目、商店、AI 数字助手。
- 管理能力：文章、友链、商品和项目的增删改、发布状态管理；订单状态核对。
- 项目预览：静态产物上传后可以预览；前后端动态项目由站长选择受信任的镜像发布到隔离运行环境，分别配置 Web 与 API 入口。
- AI：按文章内容检索相关段落，附来源链接后让可配置模型回答；模型不可用时明确提示。

## 技术选择

延续现有 Go 1.25 + Gin + GORM + PostgreSQL。前端采用 React + TypeScript + Vite。MinIO 存项目 ZIP、静态产物和头像。Redis 使用原子计数及自动过期管理助手每 IP 每分钟 20 次的共享限流，多实例共用同一额度。Elasticsearch 为已发布文章提供中英文全文检索和相关度排序；PostgreSQL 仍是事实来源，启动时重建索引，管理文章时同步更新索引，检索服务不可用时回退数据库搜索。MongoDB 和 RabbitMQ 已包含在本地 Docker 编排中，但业务尚未接入。

## 视觉方向

公开站点采用个人博客的阅读结构：首页是一幅原创傍晚小镇插画，正文是浅色背景、横向文章卡片和个人资料侧栏。项目与商品沿用同一套卡片、颜色和字号规则。参考站点为 `http://mrzym.top/#/home`，只借鉴页面组织和阅读节奏；封面图由项目单独生成，存放在 `web/public/images/riverside-dusk.png`。封面缓慢漂移、版块滚动进场，数字助手会沿页面底部走动并在悬停时招手；减少动态效果的系统设置会关闭这些动画。

## 模块边界

| 模块 | 数据与职责 | 对外能力 |
| --- | --- | --- |
| Identity | 用户、管理员身份与会话 | 注册、登录、个人信息 |
| Publishing | 文章、标签、友链 | 公开查询，管理员维护 |
| Commerce | 商品、库存、订单 | 浏览、下单、线下付款确认 |
| Projects | 项目元数据、附件、预览地址 | 展示与管理员发布 |
| Assistant | 文章片段检索、对话 | 带出处问答、数字人状态 |

所有公开 API 使用 `/api/v1`。业务错误沿用已有的 `code/message/data` 响应契约；鉴权失败使用 HTTP 401/403，服务器异常用 HTTP 500。接口文档统一维护于 OpenAPI 3 文档，作为 Apifox 导入源。

## 数据与安全

PostgreSQL 为事实来源。上传文件使用服务器生成的对象键；校验文件大小、类型和权限。管理接口必须鉴权。静态预览 HTML 使用 CSP sandbox 和独立浏览上下文，不能访问主站登录状态。动态项目运行容器不挂载 Docker Socket、数据库凭证或宿主目录，并设置 CPU、内存与进程限制；其发布命令只在站长本机执行。可执行代码只允许站长审核镜像后部署，不在普通上传时启动。AI 只能读取已发布文章；回答带来源，不能将文章内容当成系统指令。

## 当前完成情况

- 已完成：注册与登录、管理员内容管理、文章和友链、商品及线下订单、公开项目目录、静态 ZIP 上传与 MinIO 预览、站长本地发布前后端镜像、基于公开文章的问答。
- 已完成的数字人交互：原创小人物插画、行走与招手、等待与朗读状态、浏览器语音朗读。
- 待完成：在线支付渠道、语音输入、独立运行机器与持续监测。

## 交付顺序

1. 修复现有注册接口构建问题，建立测试与规范文档。
2. 发布内容 API、数据库迁移、管理接口和公开页面。
3. 商店与线下确认订单流程。
4. 项目上传、静态预览和管理员动态发布。
5. AI 检索对话与数字小人交互。
6. 端到端验证、生产部署文档、逐模块推送 GitHub。

每个功能应独立提交并推送；未完成的能力不能在 README 中标为已完成。
